# PART 13 — UX, KEYBOARD BEHAVIOR & RESPONSIVE LAYOUT

## Objective

Polish the notebook interaction without changing the product scope.

## Prerequisites

PART-12 complete.

## Scope

- focus-to-edit behavior;
- sensible tab keyboard navigation;
- editor toolbar accessibility;
- focus-visible styles;
- Escape behavior where appropriate;
- click-outside handling;
- mobile/tablet/desktop layouts;
- compact artifacts panel;
- clear active-tab state;
- prevention of accidental destructive actions.

## Product Feel

The app should feel closer to a calm digital notebook than an administration panel.

Avoid excessive modals, dense tables, and dashboard-style metric cards.

## Acceptance Checklist

- [ ] keyboard users can reach subjects and notes;
- [ ] focused controls are visible;
- [ ] clicking note text reliably enters edit mode;
- [ ] clicking outside behaves predictably;
- [ ] layout works on narrow screens;
- [ ] destructive actions require intentional confirmation.
